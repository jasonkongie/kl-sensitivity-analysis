# Mixed-Precision Quantization — OpenVINO IR Pipeline

Produces quantized OpenVINO IR models (`.xml` / `.bin`) for Mamba and Mamba-2
from pre-converted FP16 baselines, using NNCF `compress_weights` guided by
per-layer KL-divergence sensitivity scores.

## Prerequisites

- OpenVINO and NNCF installed (`pip install openvino nncf`)
- FP16 baseline models already exported to `ov_models/` via XAMBA
- Sensitivity JSON files present (generated by the sensitivity analysis stage)

## Files

| File | Description |
|---|---|
| `quantize_uniform.py` | Uniform INT8 and INT4 endpoints for all models |
| `quantize_mixed.py` | KL-guided mixed INT4/INT8/FP16 — CPU pipeline (Mamba-130M, Mamba-1.4B) |
| `quantize_mixed_gpu.py` | KL-guided mixed INT8/FP16 — GPU pipeline (Mamba-2 130M) |
| `quantize_mixed_gpu_int4.py` | KL-guided mixed INT4/INT8/FP16 — GPU INT4 pipeline |

## Sensitivity Metric

All scripts share a single constant that controls which sensitivity metric
drives the mixed-precision assignment:

```python
SENSITIVITY_METRIC = "kl_student_to_teacher"   # or "sqnr_db"
METRIC_TAG         = "kl"                       # embedded in all output filenames
```

Changing `SENSITIVITY_METRIC` propagates automatically to all output filenames,
keeping KL and SQNR experimental runs fully separated on disk.

## Output Naming

| Script | Output pattern |
|---|---|
| `quantize_uniform.py` | `{model}_uniform_int8.xml`, `{model}_uniform_int4.xml` |
| `quantize_mixed.py` | `{model}_kl_point01.xml` … `{model}_kl_point10.xml` |
| `quantize_mixed_gpu.py` | `{model}_gpu_kl_point01.xml` … `{model}_gpu_kl_point08.xml` |
| `quantize_mixed_gpu_int4.py` | `{model}_gpu_int4_kl_point01.xml` … `{model}_gpu_int4_kl_point10.xml` |

## Usage

Run in order:

```bash
# 1. Uniform baselines (INT8 and INT4 endpoints)
python quantize_uniform.py

# 2. KL-guided mixed-precision — CPU
python quantize_mixed.py

# 3. KL-guided mixed-precision — GPU (INT8/FP16, capped at 8 points for Mamba-2)
python quantize_mixed_gpu.py

# 4. KL-guided mixed-precision — GPU INT4 (optional)
python quantize_mixed_gpu_int4.py
```

All output models are written to `ov_models/`.

## Notes

- **Mamba-2 GPU point cap**: `quantize_mixed_gpu.py` caps Mamba-2 at 8 points
  (`point09`/`point10` fail GPU compilation due to the XAMBA CumBA MatMul node
  having no INT8 kernel on Intel Lunar Lake iGPU).
- **Mixed-precision assignment**: The 10 configurations `p01`–`p10` divide the
  KL-ranked layer list into equal segments. `p01` quantizes only the least
  sensitive layers; `p10` approaches near-uniform quantization.
- **Layer exclusions**: SSM `conv1d` layers (OV type `Convolution`) are excluded
  from quantization in all scripts. XAMBA CumBA MatMul nodes are additionally
  excluded for Mamba-2 GPU models.

## On-Device Profiling: Reproducibility Guide

All profiling scripts target Intel Lunar Lake via OpenVINO. The pipeline runs in three stages.

### Step 1 — Convert and Quantize

```bash
python convert.py             # base models
python quantize_uniform.py    # INT8 / INT4
python quantize_mixed.py      # KL M-P (CPU)
python quantize_mixed_gpu.py  # KL M-P (GPU)
```

The sensitivity metric is controlled by a constant inside each script.
All output filenames automatically inherit the selected tag
(e.g., `mamba-130m-hf_kl_point05.xml`):

```python
SENSITIVITY_METRIC = "kl_student_to_teacher"
METRIC_TAG = "kl"
```

The ten configurations **p01–p10** are produced by splitting the
sensitivity-ranked layer list into equal segments.
Configuration **p01** quantizes only the least sensitive layers,
while **p10** approaches near-uniform quantization.

### Step 2 — Benchmark

```bash
python benchmark.py      # CPU latency + throughput
python benchmark_gpu.py  # GPU latency + throughput
```

Each model is evaluated using the OpenVINO `benchmark_app` tool:

```bash
benchmark_app -m <model>.xml \
  -d CPU -hint latency \
  -t 60 -niter 50 \
  --inference_only TRUE
```

The flags `-t 60` and `-niter 50` ensure that each run executes for at least
60 seconds and at least 50 iterations, whichever takes longer.

Results are written to `log/benchmark_log/` as per-model text logs and a
summary CSV file: `latency_throughput_{device}_{tag}_report.csv`.

```bash
python eval_perplexity.py      # CPU, WikiText-2 PPL
python eval_perplexity_gpu.py  # GPU, WikiText-2 PPL
```

Perplexity is computed on the WikiText-2 test set.
Fake quantization is applied to replicate each configuration's
weight precision during evaluation.

```python
ds = load_dataset(
    "wikitext", "wikitext-2-raw-v1", split="test")
text = "\n\n".join(
    t for t in ds["text"] if t.strip())
```

Results are stored in `perplexity_results_{tag}.json` with the structure:

```json
{model: {point: perplexity}}
```

This format allows direct comparison across sensitivity metrics and model scales.
